# HTML 슬라이드 편집기 v4.1

HTML로 만든 강의 슬라이드와 문서를 브라우저에서 바로 고치는 편집기입니다. 서버 없이 GitHub Pages에서 돌아가고, 파일은 사용자의 컴퓨터(또는 본인 구글 드라이브)와 브라우저 사이에서만 오갑니다.

주소: https://teo-kt.github.io/lecture-editor/ · 이전 편집기(v3): https://teo-kt.github.io/lecture-editor/legacy/

## v4에서 달라진 점

v3까지는 덱을 편집 화면에 그대로 띄우고 그 DOM을 고친 뒤 통째로 저장했습니다. 그래서 덱이 실행 중에 바꾼 것(자동 맞춤 배율, 현재 슬라이드 표시 클래스, 탭 상태 같은 것)이 파일에 섞여 들어갔고, 덱에 붙은 넘기기·편집 스크립트가 편집기의 클릭과 키 입력을 가로채 선택이나 글자 편집이 엉키곤 했습니다.

v4는 구조를 새로 짰습니다.

- 원본 모델: 열린 HTML을 별도의 문서 사본(원본 모델)으로 들고 있고, 모든 편집은 "이 요소의 CSS를 바꾼다", "이 자리에 넣는다" 같은 작은 연산으로 원본 모델과 화면에 함께 적용됩니다. 저장은 원본 모델만 직렬화하므로 덱 스크립트가 실행 중에 만든 변화는 저장 파일에 들어가지 않습니다. 실행 취소·다시 실행도 이 연산의 역연산으로 처리해 화면을 다시 그리지 않고 즉시 되돌립니다.
- 격리된 편집 화면: 덱은 `sandbox="allow-scripts"` 프레임(불투명 출처)에서 실행됩니다. 덱 스크립트는 편집기 화면이나 드라이브 토큰에 접근할 수 없고, 편집기와는 매번 새로 만드는 확인값을 붙인 메시지로만 대화합니다.
- 입력 가로채기: 편집 모드에서는 편집기가 클릭·키·휠 입력을 덱보다 먼저 받아 덱의 넘기기·편집 단축키가 동작하지 않게 막습니다. 덱의 원래 동작을 확인하고 싶으면 도구모음의 [상호작용] 모드나 미리보기를 쓰면 됩니다.
- 실행 환경 보정: 불투명 출처에서 오류를 내는 localStorage·sessionStorage·쿠키·history API를 안전한 대체물로 바꾸고, alert·confirm·print와 자동 재생은 막습니다. 덱 스크립트가 시작하다 멈추는 일이 줄어듭니다.
- 슬라이드 인식: reveal.js, Marp, impress.js, Swiper, Shower, WebSlides, deck.js, 고정 무대(`#stage`·`#deck`)형 1920×1080 덱, `section.slide`·`.slide`·`[data-slide]`·`.page`형 덱, 스크롤형 덱을 자동으로 알아보고 한 번에 한 장씩 보여 줍니다. 슬라이드가 스크립트로만 만들어지는 덱은 알림을 띄우고 [정적 슬라이드로 변환]을 제안합니다. 슬라이드가 없는 일반 문서는 문서 모드로 엽니다. 꾸밈 없는 `<section>`만 있는 문서는 페이지가 그 섹션에 맞춰 스크롤되거나(scroll-snap), 섹션마다 화면 한 장 높이이고 섹션 밖에 표지·제목·본문이 없을 때만 슬라이드로 봅니다(v4.1.1). 그렇지 않으면 섹션이 여러 개여도 문서 하나로 엽니다.

## 기능

- 화면: 메뉴 막대(파일·편집·삽입·서식·배치·슬라이드·보기·도움말), 도구모음, 왼쪽 슬라이드 목록·레이어, 가운데 캔버스, 오른쪽 속성 패널. 밝은 테마와 어두운 테마를 지원합니다.
- 선택: 첫 클릭은 배경·테두리가 있는 상자를, 한 번 더 누르면 한 단계 안쪽을 잡습니다. ⌘/Ctrl+클릭은 가장 안쪽 요소, Shift+클릭은 여러 개 선택, 빈 곳에서 끌면 범위 선택입니다. 오른쪽 위 경로 칩이나 Alt+↑로 바깥 요소를 고릅니다.
- 배치: 끌어서 옮기기(슬라이드와 다른 요소의 가장자리·가운데에 맞춤 안내선), 8방향 핸들로 크기 조절(그림은 비율 유지), 화살표로 1px·Shift+화살표로 10px 이동, 정렬·간격 맞춤·앞뒤 순서.
- 글자: 두 번 클릭하거나 Enter로 글자 편집. 글꼴(구글 폰트·Pretendard), 크기, 굵게·기울임·밑줄·취소선, 색·형광펜, 정렬, 목록, 링크. 편집 중에는 고른 글자에만 적용됩니다.
- 삽입: 글상자, 도형(사각형·둥근 사각형·원·삼각형·선·화살표), 그림(파일·붙여넣기·끌어 놓기, 큰 그림은 자동 축소), 표, 구분선, 버튼, 동영상(YouTube·Vimeo·mp4), HTML 조각.
- 속성 패널: 위치·크기, 채우기·테두리(굵기·선 종류·색)·모서리·그림자·투명도, 글자, 그림, 링크, 표(행·열 추가·삭제), 여백, 고급(class·인라인 CSS·HTML 직접 편집). 아무것도 고르지 않으면 슬라이드 배경과 발표자 노트를 고칩니다.
- 슬라이드: 목록에서 끌어 순서 바꾸기, 새 슬라이드·복제·삭제·위아래 이동. 모두 실행 취소됩니다.
- 우클릭 메뉴: 캔버스와 슬라이드 목록에서 상황에 맞는 명령을 띄웁니다.
- 복사·붙여넣기: 편집기 안에서는 요소 그대로, 다른 프로그램에서 온 서식 있는 글·그림도 붙여넣습니다. 외부에서 온 HTML의 스크립트·iframe·이벤트 속성은 지웁니다.
- 저장: 열기로 연 파일은 같은 파일에 덮어씁니다(Chrome·Edge). 다른 이름으로 저장, 다운로드, 드라이브 저장을 지원합니다. 편집 중인 내용은 3초마다 브라우저(IndexedDB)에 임시 저장해 창이 닫혀도 복구를 제안합니다.
- 내보내기: PDF(슬라이드 1장 = 1페이지, 고화질 선택 가능), 인쇄 창, 현재 슬라이드 PNG, 정적 슬라이드 변환.
- 미리보기: 현재 슬라이드부터 덱의 원래 스크립트로 발표 화면을 띄웁니다. Esc로 닫습니다.
- 폴더 연결: 상대 경로 그림·CSS를 쓰는 파일은 [파일 → 그림 폴더 연결]로 해당 폴더를 고르면 편집 화면에 그림이 보입니다(저장 파일의 경로는 바뀌지 않습니다).

## 파일 구성과 배포

```
index.html          편집기 화면
css/app.css         스타일
js/                 스크립트(공용 이름공간 window.LE, 모듈 번들러 없음)
  bridge.js         편집 프레임에 주입되는 엔진(인식·격리·선택·편집)
  source.js         원본 모델과 연산
  model.js          실행 취소 기록
  view.js           편집 프레임 관리·확대
  overlay.js        선택 상자·핸들·안내선
  panels.js         슬라이드 목록·레이어
  inspector.js      속성 패널
  insert.js         삽입·복사·붙여넣기
  commands.js       명령·단축키
  menus.js          메뉴·도구모음
  io.js             열기·저장·내보내기·임시 저장
  drive.js          구글 드라이브
  present.js        미리보기
  host.js           편집기를 띄운 서버와 잇기(아래 '다른 서버에 붙이기')
  app.js            시작과 연결
drive-config.js     드라이브 공개 식별자
legacy/             이전 편집기 v3(단일 파일)
```

main 브랜치 루트를 GitHub Pages로 배포합니다(Settings → Pages → Deploy from a branch → main / root). 위 파일과 폴더를 모두 올리면 됩니다. 브라우저 캐시 때문에 고친 파일이 늦게 반영되면 `index.html`의 `?v=` 값을 올립니다. 외부 라이브러리는 필요할 때만 불러옵니다(PDF는 jsPDF, 썸네일·PNG는 html-to-image, 드라이브는 구글 라이브러리).

## 다른 서버에 붙이기 (v4.1)

편집기를 자기 서버에서 띄우는 곳(예: 발표 덱 서버)은 스크립트보다 먼저 `window.LE_HOST`를 정의해 편집기를 그 서버와 이을 수 있습니다. 이 값이 없으면(GitHub Pages 판) 아무것도 달라지지 않습니다.

```js
window.LE_HOST = { name: '테오 슬라이드', api: '/api', home: '/', present: '/d/{slug}/', legacy: 'https://teo-kt.github.io/lecture-editor/legacy/' };
```

이 값이 있으면 첫 화면과 파일 메뉴의 드라이브 항목이 [서버에서 열기]·[서버에 새 덱으로 올리기]·[저장된 판을 발표 화면으로 열기]로 바뀌고, 그 서버에서 연 덱은 저장(⌘S)하면 같은 덱에 저장됩니다. 주소에 `?deck=<슬러그>&slide=<n>`을 붙이면 그 덱의 그 장부터 엽니다. 서버는 로그인한 사용자에게만 다음을 답해야 합니다.

| 요청 | 답 |
|---|---|
| `GET {api}/decks` | `[{ slug, title, slides, updated }]` |
| `GET {api}/decks/<slug>/source` | `{ slug, title, html, rev, base }` (base는 덱 안 `media/…` 같은 상대 경로가 가리킬 주소) |
| `POST {api}/decks/<slug>/source` | 본문은 HTML, 머리글 `X-Deck: 1`·`X-Rev: <rev>`(덮어쓰기는 `X-Force: 1`). `{ ok, rev }`, 판이 다르면 409 |
| `POST {api}/upload` | 본문은 HTML, 머리글 `X-Deck: 1`·`X-Filename`·`X-Title`. `{ ok, slug, rev, base }` |

편집 화면은 출처가 없는 샌드박스 틀이라 브라우저가 그 틀에서 이 컴퓨터나 사설망 주소로 가는 요청을 막습니다. 그래서 덱의 `media/` 그림·영상은 편집기 창이 서버에서 받아 편집 화면에만 data URL로 넘기고(파일 하나 40MB, 합계 150MB까지), 저장 파일의 경로는 그대로 둡니다.

## 구글 드라이브 연동

[파일 → 구글 드라이브에서 열기]를 누르면 구글 로그인 뒤 구글의 파일 선택창(Picker)이 뜹니다. 고른 파일은 편집기에 열리고, 이후 저장(⌘S)하면 드라이브의 같은 파일에 반영됩니다. 다른 곳에서 파일이 바뀐 뒤라면 덮어쓰기 전에 확인을 받습니다. 로컬에서 연 파일도 [파일 → 드라이브에 새 파일로 저장]으로 올릴 수 있습니다.

### 보안 설계

- 최소 권한(`drive.file`): 편집기는 사용자가 선택창에서 직접 고른 파일과 편집기가 만든 파일에만 접근합니다. 드라이브의 다른 파일은 목록도 볼 수 없습니다. 구글이 민감하지 않은 범위로 분류하므로 별도 앱 심사가 필요 없습니다.
- 토큰은 메모리에만: 액세스 토큰은 localStorage·쿠키에 저장하지 않고 페이지 메모리(클로저)에만 두며 1시간 안에 만료됩니다. [구글 드라이브 연결 해제]는 토큰을 즉시 폐기합니다.
- 격리: 편집 중인 덱의 스크립트는 샌드박스 프레임에서 돌기 때문에 토큰이 있는 편집기 화면에 접근할 수 없습니다.
- 지연 로드: 구글 라이브러리는 드라이브 기능을 처음 쓸 때만 불러옵니다.
- 공개 식별자만 저장소에 둡니다: `drive-config.js`의 CLIENT_ID · API_KEY · APP_ID는 비밀값이 아닙니다. OAuth 클라이언트는 승인된 원본(`https://teo-kt.github.io`)에서만, API 키는 HTTP 리퍼러 제한을 건 상태에서만 동작하도록 설정해 두어야 합니다.
- 파일 내용은 브라우저와 구글 사이에서만 오갑니다. 이 사이트에는 서버가 없습니다.

### 설정 (본인 GCP 프로젝트를 쓰려면)

1. [Google Cloud Console](https://console.cloud.google.com/) → API 및 서비스 → 라이브러리에서 Google Drive API와 Google Picker API를 사용 설정합니다.
2. 사용자 인증 정보 → API 키를 만들고, 애플리케이션 제한(HTTP 리퍼러)에 `https://<사용자명>.github.io/*`를 넣고 API 제한을 Drive API·Picker API로 한정합니다.
3. OAuth 클라이언트 ID(웹 애플리케이션)를 만들고 승인된 자바스크립트 원본에 `https://<사용자명>.github.io`를 넣습니다(리다이렉트 URI는 필요 없습니다).
4. OAuth 동의 화면이 "테스트" 상태라면 테스트 사용자에 본인 계정을 넣습니다.
5. `drive-config.js`에 세 값을 채웁니다. 비워 두면 드라이브 버튼은 안내만 띄우고 나머지 기능은 그대로 동작합니다.

드라이브 연동은 `http(s)`로 접속했을 때만 동작합니다. `file://`로 직접 연 경우에는 안내가 뜹니다.

## 알려진 한계

- PDF·썸네일은 슬라이드를 그림으로 떠서 만듭니다. 일부 CSS 효과(복잡한 SVG 필터, 혼합 모드, 교차 출처 그림)는 화면과 조금 다르게 찍힐 수 있습니다. 글자를 선택할 수 있는 PDF가 필요하면 [인쇄 / PDF 저장(인쇄 창)]을 쓰세요.
- 스크립트가 슬라이드를 매번 새로 만드는 덱은 실행 중에 생긴 요소를 고칠 수 없습니다. 이런 덱은 [정적 슬라이드로 변환] 뒤에 편집합니다.
- 같은 파일 덮어쓰기는 File System Access API를 지원하는 Chrome·Edge에서만 됩니다. 다른 브라우저에서는 다운로드로 저장합니다.
